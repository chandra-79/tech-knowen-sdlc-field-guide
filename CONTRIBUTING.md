# Contributing to the SDLC Field Guide

Useful contributions improve accuracy, clarity, accessibility or the learning journey. Keep the main explanations understandable without an IT background.

## Report a problem

Open an issue with:

1. The page or document title and the relevant requirement/test ID, if any.
2. What is unclear or incorrect.
3. The expected explanation or behaviour and a reliable source when applicable.
4. Reproduction steps, browser and starting demo balances for an interaction defect.

Use fictional data only. Do not post real credentials, account information or personal records.

## Suggest a change

Explain the learner need and the affected documents. A change to a banking rule should keep the SRS, FRD, designs, demo, tests and user guidance consistent. Do not silently change a proposed-only example into implemented behaviour.

The site is contained in `index.html`. Small pull requests with a clear before/after example are easier to review. Verify relevant journeys and preserve the absence of in-site download/export controls.

## Meaningful checks

- All six banking tasks and their rejection/cancellation paths.
- Exact money arithmetic, transfer conservation and no partial commits.
- Session end and repeated confirmation behaviour.
- Document links, search, self-check answer feedback and keyboard navigation.
- Narrow-screen layout, both colour modes and no required external requests.

The maintainers review contributions. Submitting a change does not mean it has been accepted or released.
